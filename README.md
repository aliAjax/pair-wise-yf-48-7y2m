# pair-wise-yf-48 建筑设计竞赛匿名评审

源提示词摘要：主办方设置评分维度、权重和提交规则，评委在匿名状态下独立查看方案、打分、填写意见、声明利益冲突和保存草稿；系统提供提交进度、异常分处理、结果锁定与并列排名规则。

## 技术栈

Vue3、TypeScript、Vite、Naive UI、Pinia、Vue Router、Axios、VueUse、VeeValidate、Zod、Vue I18n。

## 本地运行

```bash
npm install
npm run dev
npm run build
npm test
```

## 并发与一致性规则（本期实现）

为演示真实后端语义，`src/services/mockServer.ts` 以 localStorage 为“服务端”、BroadcastChannel 跨标签页广播，
每个浏览器窗口（标签页）是一个独立评委端；右上角可一键切换“断网/恢复”。

1. **权重版本化**：主办方调整权重后版本号 +1。旧权重下的草稿与**已提交评分**一律失效（`submitted=false`），
   评委按新权重重新确认前，不计入提交进度、有效评分和主办方排名（方案标记“旧版待重认”）。
2. **两窗口并发提交同一评委评分**：提交携带基准 `rev` 与确认时间。两个窗口的确认都到达时**后确认者胜**；
   较早的确认收到冲突响应——已填好的本地分值原样保留（不覆盖、不丢失），界面给出
   “以本地版本覆盖提交”或“采用对方版本”两个选择；冲突项停止自动重试。
3. **锁定纪律**：锁定前评委退回修改、声明/撤销利益冲突都会即时重算提交进度、有效评分与排名；
   锁定后保存、提交、退回、利益冲突、调权重全部拒绝（断网积压的请求恢复后续传时也会收到终态拒绝）。
4. **失败重试（outbox）**：断网时操作先写入每窗口独立的待重试记录（localStorage 持久化），
   网络恢复、标签页重新可见或应用重启后自动串行续传；每个操作带 `opId`，服务端幂等去重，不重复提交。

### 手工演示

- 开两个浏览器标签页，都选择“评委-林策”（侧边栏显示不同窗口编号），进入同一方案几乎同时点提交，观察后确认者胜与冲突横幅。
- 切到“主办方”调权重（保持合计 100%），再切回评委页，看到“旧版待重认”，重认前后分别观察提交进度与锁定按钮。
- 断网后填写并保存/提交 → 右上角队列出现“待重试”；恢复网络后自动清空且服务端只有一条记录（审计事件去重）。

### 自动化测试

- `tests/store-flow.ts`：双窗口 store 集成 33 项断言（outbox、本地草稿保留、冲突解决、派生重算、排名）。
